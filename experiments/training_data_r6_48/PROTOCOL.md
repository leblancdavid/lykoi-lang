# R6.48 bounded dataset-production protocol

Owner authorization is the R6.48 12-episode user request. No model training,
downloads, installations, new semantics, H1/H2 benchmark or P6-A04/P6-A05 work.
Only new round-local files may be written. Existing implementation files and
R6.3–R6.47 identities remain pinned by the inherited preservation chain.

No independently controlled commissioner/reviewer/custodian is supplied. The
same coordinator commissions synthetic human-style requests, formalizes them,
derives acceptance and authors construction scripts. This fallback is disclosed
before generation. It cannot satisfy independent/leakage-qualified admission.
No human authorship, independent review, hidden reasoning or semantic MCP calls
will be invented. Actual deterministic API calls are retained separately as
scripted trajectories. The OpenCode patch operations are not semantic tool calls.

Stages: baseline verification → partition plan → six commissioning records and
twelve sources → ambiguity review → frozen FRC/acceptance → source hash seal →
separate construction code → validation → three fresh Python process executions
→ admission/leakage analysis → publication verification. Refuse preexisting
outputs. Source freeze verification is mandatory on construction and every replay.
Incomplete FRCs are blocked. Nonrepresentable remote-effect obligations receive
capability assessments, not host-language implementations or passing fixtures.

Four development families and two evaluation-quarantine families are assigned
before implementations. Quarantine is an export exclusion, not a secrecy claim.
Shared stateless byte/read/check scaffolds and all exposed evaluation material
must be disclosed. Twelve episodes/six families are a process demonstration.
Exports contain only admitted development episodes; an empty export is valid.

Finite acceptance compares literal expected outputs/errors/provenance with
normative artifact-resolved sites. Replays compare complete result envelopes,
including logical work, without AI. Exact nonzero work is replay-qualified only.
Preserve first failures; no expectation edits from candidate results. Any needed
expectation correction requires a separately versioned successor review.

Publication includes canonical JSON (sorted keys, ASCII escaped, compact, LF
terminator, no NaN), SHA256 raw-byte identities, schema, explicit null artifacts
for blocked episodes, rejection ledger and empty or populated training manifest.
Verify inherited and new identities, serialization, schema checks, episode links,
whitespace, credential patterns, scope and `git diff --check`. Stop on publication.
