## Seam and implementation deliverables

The [versioned normal-path specification](../../../docs/collection-query-normal-path-v1.md)
documents every stage. Original normal formalization accepted opaque FRC parameters
without assigning typed query meanings. Normal structural/V1/author dispatchers did
not route the prospective R5.98 facets. Typed information was **never produced** by
that normal interface, rather than lost by an already-typed compiler transformation.

| Deliverable | Implementation |
| --- | --- |
| Typed FRC relations | Normal FRC-0.1 `filter_order` profile: exactly `{query,facet,value}`, one obligation for each R5.98 facet. |
| Formalizer interface/schema | `lykoi_workspace/query_schema.py`, normal AI adapter output schema/validation and Workspace full cross-facet validation/profile guidance. |
| Clarification/policies | Normal `ask/answer`, lineage/revision and adopted policies; unresolved policy stays null plus blocking question/issue, never guessed. |
| SOI/reconciliation | Exact typed relations can differ in display prose; source commitments/spans, authorized references, material items, context, policies and owner approval still required. |
| Projection/coverage | `lykoi_pipeline.contracts` dispatch through `query_profile.py` to unchanged R5.98 semantics; no English parsing, benchmark IDs or partial-completeness escape. |
| BDI/adequacy | Existing query BDI and unchanged adequacy engine with normal native artifacts/pregrant refusal. |
| Normal V1/profile | Explicit reconciled `capability_profile: collection-query-1`; `LykoiContractV1` contains faithful `CollectionQueryDocumentV1`. Old unselected contracts and V1 retain their semantics/refusal. |
| Author/compiler | Normal restricted worker emits `LykoiProgram-1` from authorized V1; normal pipeline build and compiler CLI dispatch via `air_compiler/profiles.py`; controller rejects substitution. |
| Generic task/store adapter | Declared validated `model_state`; full existing store validation, nonnullable typed view, complete detached result payload, unchanged bytes/absence and retained legacy commands. |
| External verification | Independent preauthor source-bound plans; exact JSON/error channels, legacy command checks and storage preservation via fresh external processes. |

No predicate family was added. R5.98 query compiler/runtime, facets, corpus/tests
and standalone semantics are unchanged. Existing nullable task payload fields are
validated by the old model and returned unchanged; they cannot become nullable
predicate/order fields. Missing collection fields are refused, not invented.

## Authority and evidential limits

Use of OpenAI `openai/gpt-6.1-sol` and compatible CPython 3.14.3 is recorded.
Initial R5.98 working-tree work was preserved; an external commit made it tracked
before the R5.99 snapshot. This agent made no commit. No machine/model/runtime/
OpenCode/transport qualification or activation work occurred.

Captures emit typed FRC through `ModelAdapter`, rather than constructing typed query
documents after formalization. The input source is exact-bound. Source-only reviewer
inputs never contain the candidate, and inventory display descriptions intentionally
differ. Meaning/authority omissions and context mismatches block reconciliation;
normal approval, WHAT seals, plan seals, grants and reservations actually execute.

Formalizer captures, analytical inventory and literal WHAT-side oracle share one
active-agent context. Separate session IDs/processes do not prove independent
cognition. Correlated source misunderstanding/omission remains possible. Human
approvals are synthetic owner actions, not real-user approval or production
deployment. Capture replay refuses new uncaptured prose; normal AI callbacks/schema
can emit the profile, but arbitrary live-source formalization accuracy is unverified.
