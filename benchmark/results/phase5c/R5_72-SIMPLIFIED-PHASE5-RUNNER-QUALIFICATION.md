## Architecture and research scope

Core implementation:

- `benchmark/evaluation/phase5_runner_v2.py`: state/commitment capture, canonical
  evidence, secret-safe persistence, protected-path boundary, health binding,
  freeze, one-time authorization, durable ledger, observation and post-check.
- `benchmark/evaluation/phase5_worker_v2.py`: explicit generic worker selections,
  pre-import exclusions, generic matrix/schema/traceability/contamination checks
  and offline AI-independence probes.

Qualification support consists of an independent 30-test suite, the bounded
qualification driver and a separate read-only final auditor. None executes old
QualifiedAuthority, capsules, certificates, historical physical locks, adapters
or stopped production chains. Source AST inspection checks this import boundary.
Historical semantic/compiler component filenames remain ordinary current
implementation components; historical evaluation mechanisms are not imported.

The experiment asks whether Lykoi satisfies **required externally observable
behavior**, not whether it produces conventional source, generated code or the
same internal representation. The synthetic evaluator demonstrates dispatch and
whole-resource-set coverage; it does not establish B02 support or acceptance.

## Bounded worker execution

Eight fixed stage names select one pinned worker module. Each health subprocess
has an **85-second timeout** inside a **110-second tool call**, leaving headroom
for capture, startup, publication and final capture. Git metadata calls have
15-second timeouts. Stages persist individually as canonical health records bound
to the same CurrentState, then aggregate into one health identity. There are no
historical receipts, continuation certificates or general capability registries.

The worker receives only needed Windows runtime/temp context and fixed Python
controls. Provider credentials and authoring variables are not propagated. The
protected boundary is installed before worker test imports. Ordinary generated
application descendants come from reviewed generic tests and inherit the stripped
environment; this is cooperative fixed-worker execution, not a native-code sandbox.

## ObservationLedger, synthetic lifecycle and PostObservationCheck

The ledger uses exclusive-create, flush/fsync, canonical hash-linked events:

`AUTHORIZED → OPENING_RESERVED → OPENING_CONSUMED → DISPATCHED → COMPLETED`

## Adversarial qualification

Thirty independent tests cover the complete lifecycle and these negative cases:

- Wrong commitment; missing/substituted sealed metadata; missing/substituted opened
  resources: reject before dispatch; mismatched opening remains consumed/incomplete.
- State mutation before opening, runner mutation, stale aggregate or individual
  health and missing health: reject.
- Second observation, second authorization and cross-ledger replay: reject without
  another callback. Interrupted opening/dispatch: incomplete and nonretryable.
- Repair marker after observation and post-observation state mutation: invalidate
  or reject the post-check.
- Generation/execution/acceptance under static authorization: reject before opening.
- Actual benchmark authorization: prohibited in R5.72. All 11 actual paths and 12
  bytecode aliases are designated. The denial hook is exercised on disposable
  **fake protected content**, never by attempting a real B02 read; swallowed denial
  still produces `R5_72_PROTOCOL_HALT`.
- Credential-field/recognizable/marked-secret publication: reject before file
  creation. A secret-bearing observation result leaves dispatch incomplete.
- Development AI environment mutation: fixed-source identity unchanged and authoring
  variables absent from worker context; offline core meaning/output invariant.
- Pre-import exclusions, ledger corruption, canonical immutable reload and exclusive
  publication: pass their independent witnesses.
