# R6.13 threats to validity

1. **Correlated review:** R6.12 authors/preparer/reviewer and current R6.13 reviewer
   use the same model family/identity context. No independent-model confirmation,
   separate curator, controlled cognition or statistically independent qualification.
2. **Task sourcing:** five synthetic tasks, not independent external requests. The
   initial preparer inherited capability summaries. Adversarial cases deliberately
   target documented omissions, not randomly sampled independent generalization.
3. **Known implementation exposure:** original candidates/review/outcomes were known
   before suite preparation. New expectations are contract-derived and frozen before
   any R6.13 execution, but this is exposed challenge coverage, not a blind test.
4. **Finite acceptance:** 68 successor entries, of which three exactly overlap old
   inputs; 65 additional task inputs, not 68 independent sources. Thirty base repeats
   on modified candidates and 48 original repeats are explicit. Shapes/error cross
   products and all valid states remain unexhausted. No universal correctness claim.
5. **Scorer changes:** duplicate keys at every depth/nonfinite JSON/UTF-8 output
   fail explicitly. Exact observable comparisons apply equally to all tracks, but
   B/C have no historical executable so symmetry of rules is not matched execution.
   Synthetic scorer regression tests are same-author tests, not independent auditing.
6. **Budget limits:** historical caps are not retrospectively enforced. New direct
   process timeouts and cooperative session deadlines are exercised; process startup,
   cleanup, OS scheduling, descendants and the whole AI session lack hard containment.
   The first probe attempt had only a terminal-tool limit, lost unpublished in-memory
   observations and lacks measured UTC completion. Later individually budgeted probe
   execution is labeled separately, not first-attempt authoring success.
7. **Capability uncertainty:** no scored B/C full program, no necessary construction
   size bound, no kernel impossibility proof. Successful partial XOR/Boolean/prefix
   observations qualify static conclusions but do not repair all task bindings. The
   full-byte lookup timeout is evidence of one inappropriate naive construction,
   not all finite strategies. Validation cost is outside VM runtime work accounting.
8. **Effort telemetry:** no new AI authoring trials. Tokens, authoring time and repair
   efficiency have not been remeasured; replay timings are only process overhead.
   Prior late-recovered usage/unavailable billing/isolation/settings limits remain.
9. **Small correlated sample:** five base tasks/three changes, no repeated authoring
   trials or matched-success set, no causal timing controls or variance estimate.
   No statistically significant or general superiority conclusion is justified.
10. **Host environment:** same Windows/CPython environment, process scheduling and
    transport behavior. Provider-neutral standard-library scorer/probes do not attest
    provider-hidden input isolation. No provider service used for execution.

`R6_13_SCORING_AND_REPLAY_QUALIFIED` qualifies only the bounded repaired scorer,
frozen replay and disclosed reassessment. It is not independent qualification of
Lykoi, the VM, task sourcing, model reliability or comparative superiority.
