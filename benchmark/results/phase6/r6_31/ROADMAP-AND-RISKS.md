## Essential, optional and future work

**Essential:** exact equivalent base fixtures; admission/storage/retrieval/edit
snapshots; dependency closure updates; explicit independent expectation/supersession
maps; comparable tools/budgets; durable measurements and real input-control disclosures.
Implement only enough to qualify and exercise the bounded profiles. Selection and
oracle preparation are necessary experiment work, not language implementation.

**Optional:** embedding search, graphical editors, database-backed stores, generalized
refactoring automation, complete new impact indexing, remote multi-provider matrix,
energy measurement and additional model sizes. Actual billing is required only for
a billed-cost claim; model/provider configuration attestation strengthens validity.
Hard input exclusion enables stronger claims; without it, a clearly authorized
exploratory pilot can still answer feasibility. No large isolation infrastructure
project is assumed as the only path forward.

**Future general-purpose language research:** richer types/records/lists, recursion,
dynamic loops, new effects, stateful reusable VM compositions, broad arithmetic,
universal equivalence or invariant-preservation proof. None is necessary for this
bounded design and none is authorized. No training/fine-tuning.

## Risks and unresolved questions

1. **Scope mismatch:** H1 arithmetic compositions do not establish stateful adaptive
   application design; H2 production edits do not establish VM or learned-library
   benefit. Always name the actual foundation.
2. **Small and correlated samples:** historical kiln/custody share a skeleton;
   branches/repeats are correlated. Main H2 four clusters still yields weak intervals.
3. **Task tailoring/scaffolding:** narrow supported scope and precise contracts can
   favor all structured workflows. Independent relation selection and unspecified
   implementation choices reduce, not eliminate, this bias.
4. **Input exposure:** coordinator knows previous findings; fresh processes/tool
   allowlists do not certify provider hidden context. Actual unestablished isolation
   makes results exploratory, even with no forbidden transcript markers.
5. **Ordinary macro explanation:** capacity caps are imperfect cross-language matches;
   LH actual-capacity matching may fail. Without a matched comparator no AI-discovery
   attribution. LX overload is a limit, not evidence of a superior symbol.
6. **Task-local rediscovery:** L0 can compose within a task; L1 can ignore its library.
   Report true immutable-identity transfer, not merely repeated formula shapes.
7. **Static/runtime gap:** type validity cannot ensure correct requirements, ordered
   errors or state consistency. Runtime invariants are not a static preservation proof.
8. **Impact omissions:** production legacy traversal omits extension facts. Independently
   frozen semantic footprint and raw/model-enriched outputs expose this limitation.
9. **Transport/recovery:** R6.25 authoring gap, R6.26 discovery halt and R6.30 premature
   test calls show route/tool states must qualify separately from language semantics.
10. **Metering and orchestration:** R6.30's outer timeout and missing B usage can recur.
    Flush events, own processes, retain partial native usage; missing data is null.
11. **Expectation defects:** preserve native error stages and qualify scripted witnesses
    before freeze. A correction is a successor, not a hidden historical rescore.
12. **Amortization optimism:** cheap runtime/short output does not mean cheap discovery.
    Count unused/rejected entries, index exposure, maintenance and setup sensitivity.
13. **Baseline bias:** accepted H2 equivalents measure modification conditional on
    correct bases; fixture repairs/costs and earlier failed bases must be reported.
14. **Deployment and history:** immutable successor objects must still update intended
    deployed callers. Otherwise mechanical preservation hides actual modification.

Unresolved **implementation qualification** questions: can the unchanged construction
path import exact frozen closures without resealing differences; can equivalent B/C
fixtures express all selected precedence/shared-caller rules; can requested reasoning
and full cost exports be attested; can fresh author input packages be enforced on
the available host/route? These are explicit Q0/Q1 gates, not unspecified scoring.

**Recommendation:** next authorize Q0 alone, AI-free and unscored, using exposed
scripted fixtures. Its success would establish mechanics to permit a separately
frozen pilot; it would not support H1 or H2 advantage. Stop at each published boundary.
