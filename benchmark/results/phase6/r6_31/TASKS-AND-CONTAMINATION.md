# R6.31 — Task selection, partitions and contamination controls

This round selects no scored task instances and launches no author sessions. Exact
future manifests are implementation-stage inputs, constrained by these selection
rules, not discretion to choose winners after development.

## Selection and freeze sequence

1. Pin semantic scope, track tools, model/configuration, limits, effect thresholds
   and neutral qualification requirements before commissioning tasks. Curator gets
   only public supported scope, not implementation outcomes or candidate libraries.
2. Where feasible use an independent human/task source and a different acceptance
   author. Log identity/role, input access and all selection/exclusion reasons.
   Independence cannot be supplied by a fresh chat or asserted from a role label.
3. H1 curator commissions4 development/12 evaluation contracts in predeclared
   transfer/combination/stress strata. Split by normalized behavioral skeleton:
   dependency/order graph, predicate relation, success/failure domain and consumers.
   Names/constants alone do not create a new family. Reject cross-partition near
   duplicates **before** library development. Evaluation strata are labeled before
   seeing either human or discovered vocabulary; stress need not allow beneficial reuse.
4. H2 select already-existing equivalent applications by eligibility and fixed pool
   order. Choose4 across at least2 skeletons; prepare4 changes/application outside
   modifier contexts. Modification selectors cannot inspect prospective authors'
   reasoning or optimize cases around a language's known failures. Public supported
   scope necessarily bounds selection and its bias must be disclosed.
5. Acceptance author derives expected observations, obligation-to-case coverage and
   H2 retained/superseded map from requirements alone. A second source-only review
   resolves material ambiguity before freeze. If independent staff unavailable,
   record same-coordinator design and classify task evidence exploratory.
6. Pin exact contracts, examples, oracle, identities, seeds/repeat schedule, track
   docs, known setup costs and ordered inclusion manifest. Neutral correct/wrong
   scorer fixtures qualify error stages before freeze (R6.29 lesson). No candidate
   behavior decides what an acceptance expectation should have meant.
7. H1 development runs; libraries and all proposal/rejection/cost records seal.
   LH developer sees only development requirements and no L1 bodies. Exact capacity
   matching follows the predeclared rule; no human redesign from evaluation outcomes.
8. Reveal H1 evaluation only after vocabulary/machinery seal. H2 modification
   reveal only after all equivalent base snapshots and modification seals exist.
   Reveal receipts bind recipient/session, bytes/hash, time and prior seals.

Exclude historical R6 task instances/solutions from main H1 tasks. Historical
kiln/custody may be used in exposed H2 qualification/pilot, with explicit provenance;
they are never advertised as independent development-unseen application evidence.
Neither P6-A04 acceptance nor P6-A05 sourcing/access is permitted.

## Actual input and access control

Author gets an allowlisted package: identical behavioral contract/public examples,
actual track tooling docs, permitted frozen library or own accepted base, relevant
released modification, and its own logged development feedback. No repository
AGENTS/history, coordinator findings, other-track artifacts, hidden scorer or
unreleased modifications. Use separate processes/workspaces/session identities;
disable inherited retrieval/memory and nonallowlisted tools where the runner supports
it. Do not copy this findings-bearing design context into participant system prompts.

Before primary execution test denied paths/tools, cross-track reads, hidden scorer,
unreleased task/modification, inherited guidance and unauthorized network access with
neutral probes. Retain successful as well as failed access attempts, configuration
and host/provider attestations. A prompt prohibition or marker scan is only a
procedural control. OS mount/process controls do not attest upstream provider hidden
context; provider claims have their own evidence field. Necessary inference network
may go through an allowlisted broker; deterministic application execution needs none.

Record exact supplied system/developer/user messages where accessible, schema/tools,
retrieval payloads, native exported text, context sizes, inherited-content disclosures
and unknown channels. Verify exact UTF-8 delivery. This design coordinator knows
historical outcomes; that fact is recorded, not cured by a new session name.

## Evidence-grade rules

- **CONTROLLED_WITHIN_DOCUMENTED_BOUNDARY:** relevant task/oracle/cross-track and
  withheld-change exclusion is effectively enforced, negative controls pass, and
  input/configuration attestation supports the stated boundary. Explicit residual
  pretraining/provider uncertainty remains. Do not call it universal independence.
- **EXPLORATORY / CONTAMINATED_UNENFORCED:** relevant exclusion or curator separation
  cannot be established, even with no observed leak. Continue only as a transparently
  labeled exploratory pilot if its future authorization permits that grade.
- **CONTAMINATED_OBSERVED:** actual forbidden exposure; retain all results/costs but
  remove affected cells from causal/transfer claims, not from planned-run accounting.
  Halt primary authoring on scope breach; no post-exposure vocabulary repair.
- **INCOMPLETE:** missing snapshots/reveal provenance or unresolved requirement
  ambiguity prevents a scored comparison. Preserve first blocker and downstream
  NOT_REACHED; a successor is separately authorized/versioned.

Counterbalance H1's six condition orders by cyclic rotation of task+replicate index;
H2's three tracks likewise, alternating branch order. Inference serial on the same
resource class; common cold/warm policy pinned. No shared conversational history,
cross-condition warm-cache seeding or evaluation learning. Report requested seeds
versus actual supported seeds; repeats do not prove independence. A within-condition
library persists only during H1 development and becomes read-only during evaluation.

Novelty means unseen to this experiment's development/author input history within
the evidenced boundary. Unknown model pretraining exposure is not certified absent.
Capability tailoring, fixed scope, common explicit contracts and shared oracle
plumbing may limit ecological validity even when input withholding is enforced.
