# R6.50 — Independent evaluation and training-data scaling design

**Final classification: `R6_50_INDEPENDENT_EVALUATION_GAP`.**

The bounded design is published. **Independent commissioning was not established;
withholding is not enforceable in the supplied environment.** No actual human
commissioner/reviewer was appointed, no independent family was frozen, and no hidden
sibling was authored. A neutral commissioning package and public structural sibling
brief are retained as unqualified design material. No human approval is invented.

## 1. Authorization, baseline and preservation

The active owner request authorizes bounded nonproduction research/dataset design
only, explicitly excluding training, large generation and semantic expansion.
Initial `git status --short` was clean. Before editing, the existing R6.49
publication verifier ran successfully:

`$env:PYTHONDONTWRITEBYTECODE='1'; $env:PYTHONPATH='src'; python experiments/training_data_r6_49/publication.py --check`

It verified **5,387 protected identities**, **52 publication payload files**
(1,236,864 bytes), ten successor Tier T candidates and zero Tier E examples. Its
checks include source/candidate seals, admission ledger/index, deterministic target
regeneration and stored complete replay observations. This was read-only verification,
not a new functional acceptance run, training call or historical rescore.

R6.48 remains `R6_48_DATA_PIPELINE_PARTIAL` with **zero original admissions**.
R6.49 remains `R6_49_TRAINING_DATA_PILOT_QUALIFIED`: eight separate successor
reassessments plus two new production-backed stateful episodes, **10 Tier T / 0 Tier E**.
No R6.50 record is newly admitted. The inherited protected chain plus R6.49
publication/manifest/receipt are rechecked by the new round-local read-only verifier.

Production kernel remains **26**, on unchanged R5.114 accounting and preserved
implementation identities, not a fresh semantic minimality proof. Production
compiler/lowerer/runtime, experimental implementations, canonical model and generated
production artifacts are unchanged. Historical R6.3–R6.49 classifications and
protected artifacts remain unchanged. No execution primitives, weights downloads,
dependency installs, model inference/training, large dataset generation, P6-A04

## 2. Independent evaluation and sibling custody

[Commissioning protocol](r6_50/COMMISSIONING-PROTOCOL.md) defines actual human roles,
permitted input inventories, independent pre-implementation acceptance review,
source-authoritative ambiguity resolution and hash-bound freezes. The brief requests
one original bounded local-stateful family without exposing candidate solutions or
requiring a historical release skeleton. **Commissioned families: 0; independent
acceptance reviews: 0; new source/acceptance freezes: 0.**

[Custody protocol](r6_50/CUSTODIAN-WITHHOLDING.md) defines a structural-transfer
sibling brief and separate-host/account exclusion, canary denial tests, private
identities, salted commitments, access audits and scorer-only evaluation. Neither
instructions nor hashes enforce access. **Custody deployments/tests: 0; qualified
withheld siblings: 0.** The AI-authored public sibling sketch is exposed, unqualified
evaluation material, not independent human commissioning. Actual content must be
authored privately under future qualified custody. Both primary/sibling and all
derivatives stay evaluation-only, outside training exports.

## 3. Paired data and scalable Tier T design

[Format contract](r6_50/PAIRED-EXAMPLE-FORMAT.md) and
[schema v1](r6_50/paired-example-1.schema.json) specify original source, FRC, frozen
acceptance, Lykoi target, conventional Python, independent functional observations,
validation/replay, artifact/dependency identities, family/partition, authorization
and contamination provenance. The schema is a structural design; semantic gates and
a full admission/export implementation remain future work.

Both targets must pass the same external contract and paired state/error/restart
observations. Source similarity is irrelevant. Generated Python backend output is
not a separately authored conventional counterpart. **Ten Tier T candidates do not
establish ten independently verified conventional Python/Lykoi pairs.** R6.49's
policy remains intact; this stronger paired-study view does not retroactively revoke
candidate admission. Preparation permission does not authorize actual training.

[Scaling design](r6_50/TIER-T-SCALING.md) specifies diverse behavioral axes, stateful/
stateless production, frozen source authority, validated targets, Python counterparts,
positive/negative/boundary histories, two deterministic replays, provenance, layered
dedup and fail-closed export. Renaming, numeric changes and repeats add no independent
semantic diversity. Existing five nominal families form only two broad scaffolds.
Narrow mechanics are supported by R6.49; scalable diverse paired production is not
yet empirically qualified. A later four-contract/two-component audit is proposed,
not performed or admitted here.

[Generation alternatives](r6_50/GENERATION-ALTERNATIVES.md) compare human, AI-reviewed,
deterministic-template and hybrid approaches on diversity, costs, correctness,
scale, leakage/review burden and kernel coverage. Human commissioning is necessary
for the intended independent evaluation. Hybrid training proposals with deterministic
qualification are a plausible pilot choice; no strategy is proven sufficient.

## 4. Curriculum, coverage and leakage

[Curriculum](r6_50/TRAINING-CURRICULUM.md) covers all ten requested stages and maps
all 26 preserved constructs to planned qualification observations. Production-backed
state/guards/persistence are distinguished from experimental pinned composition.
Existing admitted coverage is finite and narrow; relations, authority, migrations,
dimensioned time, multi-record order/effects and cross-feature pairs remain gaps.
No kernel coverage completion is claimed.

[Leakage specification](r6_50/LEAKAGE-CONTROLS.md) groups skeleton, template,
predecessor/successor, abstraction, oracle and tool-trajectory ancestry into connected
partition components. Evaluation solutions and acceptance stay out of training
exports. Historical exposed tasks, including B01–B20, R6.48 quarantine and R6.49
episodes, cannot be relabeled independent evaluation. P6-A05 was not inspected.

## 5. Fair comparison and resources

[Matched-adapter design](r6_50/MATCHED-ADAPTER-COMPARISON.md) uses one shared open-weight
base, one adapter per language, unchanged-base controls for both languages, equivalent
requirement distributions/contracts, measured matched token/compute budgets and
identical inference/repair caps. Representation-length differences receive explicit
token- versus episode-balanced sensitivity analysis. Tuned Lykoi against untuned
Python alone cannot support language superiority.

[Hardware assessment](r6_50/HARDWARE-RESOURCES.md) uses verified RTX4070/12GB and
nominal32GiB baseline. 1.5B LoRA/QLoRA is the conservative candidate size; 3–4B QLoRA
is plausible with short contexts, small microbatches and measured headroom. This is
unmeasured training feasibility, not a checkpoint choice or fit qualification.
Trainable tensors/tokenizer, licenses and compatible stack remain unqualified.
Effort, token/compute, evaluation, storage, local/rental and rights costs are explicit
planning scenarios. No downloads or setup were undertaken.
