# Paired training-example format — lykoi-paired-example-1

The [JSON Schema](paired-example-1.schema.json) is a versioned structural design.
It is not a newly implemented admission engine. No historical record is migrated
or promoted in this round. Shape validation alone cannot establish any gate below.

Each complete record references original requirement, source-bound FRC, pre-author
frozen acceptance, actual Lykoi semantic target, independently authored conventional
Python counterpart, functional observations, semantic validation, deterministic
replay, dependencies, rights, provenance and family partition. Artifacts have
SHA256 and byte length. `artifact_identities` inventories every referenced artifact
and transitive dependency. Use immutable UTF-8 JSON with sorted keys, no duplicates,
NaN or infinity; hash original artifact bytes, not reserialized guesses.

## Semantic requirements beyond JSON Schema

1. Resolve references only inside an authorized partition, verify byte/hash identity
   and schema/foundation versions, reject duplicate IDs and missing dependencies.
   An evaluation record's private references are resolved only by its custodian.
2. Both implementations must satisfy the **same** frozen external contract. Pair
   observations by case and history ID; compare success values, order, exact errors
   and precedence, persisted observable state and rejected-write preservation.
   Normalize only source-approved nondeterminism, pinned before candidate access.
   Equal behavior between two wrong programs is not contract acceptance.
3. Conventional Python is authored from the source/FRC without viewing the Lykoi
   target, lowering or acceptance solution. Compiler-generated Python belongs in
   the Lykoi lowering inventory; it does not fill the conventional Python field.
   Record actual independence limits if the same coordinator authored both.
4. Independent functional observations require a separate acceptance observer with
   restricted inputs, role/input evidence and actual execution records. Otherwise
   use `same_coordinator` or `unattested`, and classify the stronger paired view as
   pending. This prospective paired-study requirement does not invalidate R6.49's
   less restrictive Tier T admissions or imply every Tier T candidate is paired.
5. Freeze expected behavior before authoring. Perform at least two clean AI-free
   replays per implementation; compare complete deterministic envelopes and explicit
   normal restart histories. Preserve first failures and all authorized repairs.
   Finite functional equivalence is suite-scoped, not universal proof.
6. Actual semantic tool trajectories and editing trajectories are optional/null,
   distinct views of the same episode. Scripted lowering is not AI selection.
   Capture actual arguments, responses, corrections and tool versions if present;
   exclude hidden reasoning and credentials. Do not invent missing observations.
7. Candidate preparation and actual training permissions are separate. Rights must
   cover the source, both targets and derivatives. `training_run_authorized=false`
   is required in this round. A proposed authorization reference cannot grant rights.
8. Admission applies the unchanged R6.49 Tier T/Tier E policy plus these paired-view
   conditions. Unknown gates fail closed. `paired_verified` requires real observations
   and functional equivalence; evaluation-family records never enter training exports.

No source-code similarity, common AST, equal token length or identical internal
storage representation is required unless itself an external source obligation.
Count unique requirement episodes and connected semantic-family components,
separately from language views, representations, seeds and repeated observations.

Historical cohort: ten Tier T candidates exist. A count of ten qualified conventional
Python/Lykoi pairs or ten independent observation sets is **not established**.
