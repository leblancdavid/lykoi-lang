# Family-level training/evaluation firewall — R6.50 / version 1

The split unit is the connected ancestry/scaffold component, not a row or nominal
application name. Build a versioned graph **before training export**: nodes include
sources, FRCs, candidates, predecessor/successor, acceptance generators, application
templates, task-specific abstractions, tool trajectories and derivative artifacts.
Edges encode common skeleton, template derivation, reusable task definition, copied
oracle logic, modification lineage or substantive solution exposure.

Assign entire components to training-development, development-validation, custodian
evaluation or quarantine. Generic language semantics, tool schemas and an unchanged
compiler may be common foundations, explicitly allowlisted and hash-pinned; sharing
a generic compiler does not make every program one family. A task-specific workflow
template, acceptance generator or abstraction definition does create a family link.
Borderline commonality receives manual review and conservative grouping.

| Leakage route | Mandatory control / falsification |
| --- | --- |
| Application skeleton | Normalize fields/names and compare transition/dependency structure; group reused scaffolds |
| Template solution | Group template versions and structural derivatives; new numeric constants never justify a clean split |
| Predecessor/successor | Transitive lineage stays in one component; exclude old histories and repair examples from other partitions |
| Abstraction definition | Inventory transitive bodies/dependencies; task-specific shared definitions join components |
| Acceptance oracle | Custodian keeps tests, generator seeds, reference outputs and implementation private; fixed limited scoring feedback only |
| Tool trajectory | Group prompts, feedback, edits, replay logs, errors and caches with the source; redact credentials/hidden reasoning |

Training exporter must consume an allowlisted, sealed Tier T manifest, recompute
dependency closure and reject any evaluation/quarantine component, unknown ancestry,
unresolved authorization or missing identity. No repository-wide scrape or random
episode split. Separate data-qualification evidence (including training acceptance)
from tokenized targets; evaluation acceptance is never in the exporter input tree.
Store tokenizer/rendering/packing versions and exact exported bytes/token counts.

Preflight negative controls: injected evaluation reference; renamed evaluation
skeleton; successor of evaluation task; copied abstraction body; oracle output in
a trajectory; path traversal to custody; unknown component. Each must block export.
These are requirements for later implementation, **not controls run in R6.50**.
