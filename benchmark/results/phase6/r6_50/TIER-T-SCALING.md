# Tier T scaling design — R6.50 / version 1

Apply [R6.49 admission policy](../../../../docs/training-data-admission-r6.49.md)
without amendment. Tier T is a supervised candidate pool; Tier E additionally needs
independent commissioning/review and qualified withheld evaluation. No new admissions
or dataset instances are produced in R6.50.

## Controlled production stages

1. Plan a batch by family, behavioral structure, foundation and coverage deficit.
   Allocate stateless and stateful contracts separately; prohibit count-only quotas.
2. Register origin, rights, ancestry/template ID, exposure and component before
   authoring. Exclude evaluation components and sources with unresolved rights.
3. Resolve source ambiguity; freeze source/FRC/acceptance/harness/provider assumptions.
   Independent review is preferred for ordinary Tier T and required for the proposed
   paired-study observation qualification. AI origin stays AI origin after review.
4. Construct Lykoi on pinned existing meanings. Independently construct conventional
   Python from the same contract. Unsupported whole obligations are quarantined;
   no host callback or new primitive may silently fill a semantic gap.
5. Validate semantics and dependencies; regenerate deterministic lowering. Python
   syntax/import checks supplement functional acceptance, not replace it. Preserve
   initial candidates, exact feedback, repair counts and frozen expectations.
6. Run the external suite against both with controlled clocks/IDs/private stores;
   positive, negative, boundary, mixed-invalid, multi-record and relevant restart
   histories. Compare contract-approved observations; run two AI-free clean replays.
   Separate validator rejection, wrong behavior, oracle gap and unexecuted stages.
7. Deduplicate and audit partitions. Apply all mandatory gates, emit immutable
   admitted/rejected ledger, exact export allowlist, counts, cost and verification.

## Diversity and deduplication

Candidate axes include expression dependency shape; ordered/short-circuit checks;
sequence versus branching transitions; local one-store atomic effects; references;
nullable refinement; elapsed-time boundaries; migration source obligations; successor
modification and cross-feature composition. Domains might include local inventory,
booking or document lifecycle, but these are suggestions, not independent requirements.
Verify each axis on its actual supported profile before counting it.

Layer deduplication: exact bytes; identifier/literal-normalized symbolic and Python
structure; obligation/error-order/state-transition signatures; template/definition
dependency ancestry; manual ambiguous-near-duplicate review. Fingerprint matches
suggest duplicates; nonmatches do not prove semantic independence. Require a concrete
behavioral counterexample to count a structural variant as additional semantic
diversity. Renaming, numeric changes, compiled views and repeats add zero diversity.
Retain all provenance even when an example receives zero sampling weight.

Count: episodes, independently reviewed episodes, nominal families, connected scaffold
components, behavioral structures, construct coverage, cross-feature coverage, natural
failures and replay observations. Report both raw and deduplicated totals. R6.49's ten
episodes/five nominal families/two scaffold components are the existing starting point.

## Scaling controls and qualification

Proposed next bounded pipeline qualification, after custody setup: **four new training
contracts across two new scaffold components**, including stateful/stateless behavior
and one meaningful successor history (counted in its parent's component). Produce
conventional pairs and cost receipts, not a large corpus. Require all exported pairs
to pass both implementations/two replays, zero unresolved contradictions, complete
identities/rights, zero evaluation-component export and actual independent observations.
Seed wrong-behavior, duplicate, missing-rights and leakage controls in separate files;
require rejection. Failures remain evidence; no admission-rate target can waive gates.

Measure median/range person-hours, actual tokens, wall time, retries, bytes and reviewer
disagreements by strategy. Stop on provenance/custody breach or oracle contradiction.
Only after a successful bounded audit should the owner authorize a larger batch and
decide an empirical family/coverage target. Automated throughput and human-review
sufficiency have not been established at scale. A failed batch is not repaired by
changing acceptance from candidate outputs.
