# Leakage, provenance and independence assessment

All R6.73 requirements, fixtures and targets are coordinator-authored synthetic
controls. There was no independent reviewer or auditable independent withholding.
Expectations were frozen before reconstruction implementation and candidate execution;
one pre-execution add/le negative typo has an explicit preserved amendment. Frozen
expected values are literal arithmetic/logic observations, never candidate-derived.

[Evaluation-family reservations](EVALUATION-RESERVATIONS.json) preceded training-row
generation. E01-boundary-negation, E02-two-independent-prefixes and E03-unit-equality
have descriptions and identities only. No requirement solutions, gold decisions or
acceptance fixtures for these families are generated or published. Future evaluation
must use a separately frozen realization; this session does not create those tasks.

The coordinator knows the full vocabulary, existing demonstrations, R6.72 failures,
curriculum gaps and the proposed evaluation structures. Historical diagnostic exposure
is deliberate development context, not fresh held-out evidence. Evaluation is
**exploratory coordinator-reserved**, not independently withheld generalization.
All nine training categories share the tiny add/le/eq action interface. Reserved
structural differences are not evidence of broad distributional independence.

F01 and F02 share one le requirement with the same bindings/fixtures and different
scope names. These are correlated overlap, not an additional behavioral family.
F08/F09 share a prior-result structure. F09's le and eq golds and their wrong-relation
negatives agree on all fixtures because adjusted is echo+1. Their requirement-derived
operation identities differ; two wrong choices pass behavior but fail semantic-target
acceptance. None of these are counted as distinct generalization successes.

The immutable scope contains an output-type obligation. An Int64 obligation narrows
valid operations to add; F01 add/le therefore has an available type shortcut. le/eq
contrasts share Bool and still require relation selection. Input literals, names and
scope can legitimately narrow choices; the decoder does not filter against result
type, semantic validity or requirement expectations. Renderer validation rejects
incompatible choices instead of replacing them. The model must select both ordered
operands and explicit deps; these are not reconstructed on its behalf.

Correction-style SFT inputs explicitly label one candidate as incorrect; that label
is a supervisory scaffold. Rejection reasons stay metadata, and assistant targets are
only correct compact decisions, without invented reasoning. Future deployment evaluation
must use direct requirement prompts without incorrect-candidate hints. Performance on
hinted correction prompts would not establish unaided construction benefit. Direct and
corrective records of the same requirement must never cross train/evaluation partitions.

Tokenizer measurements used only the local pinned tokenizer. Historical S11 text entered
CPU decoder controls, not model prompts. Model calls/training/optimizer/scheduler updates
are zero. The inherited identity-only audit preserves on-disk checkpoint and adapter;
no live tensors exist in this round to fingerprint. No credentials are published.
