# Smallest learnable-skill recommendation

**Choose one typed value operation from a requirement and an explicit immutable
typed scope, with exact references/dependencies.** The initial supported vocabulary
is existing ref/const/add/le/eq under the experimental Int64/Bool/Unit wrapper.
Recommend B supervised output: one value-step object with result type and exact deps.
This is experimental construction research, not a production-language extension.

Requirement families should force meaningful alternatives: Int64 sum of two stored
values; comparison of a stored quantity against another value/literal via le;
equality comparison producing Bool via eq; repeated input reference versus two
distinct refs; subtotal reuse rather than recomputing or using the original input.
Select multiple operation/tree/reference structures and type combinations allowed
by the fixed contract. Alpha-renamings/constants can be diversity controls, not
independent semantic families. Operator choice is genuinely semantic even with a
fixed mechanical envelope. Do not provide the correct operator/AST in the input.

The scope declares prior typed bindings and result obligation; instruction supplies
the relation to construct. A proposed typed scaffold provides only signature, earlier
state, mechanical result/serialization interface and bounds. Deterministic assembly
copies the predicted node and explicitly declared result into a one-step definition,
computes canonical identity and runs unchanged validation/expansion/execution.
It must reject, not fix, wrong operations, types, deps and refs. A uses the equivalent
complete minimal package; C selects `apply_operation` with the same semantics if
its narrow existing schema is qualified. A full application, persistence or new
execution primitive is unnecessary.

Independently check outputs with source-derived finite ordinary/boundary fixtures,
Bool-versus-Int64 rejection, addition overflow and well-typed wrong-op/ref mutants.
Use a distinct expected-value evaluator for this bounded relation, frozen before
authoring, not generated target code as its own oracle. No new oracle or executions
are created here. Type/schema/dependency validation alone cannot distinguish a valid
but incorrect eq from le. For pure one-step cases error precedence is not applicable;
ordered checks are the next curriculum stage, not a claimed outcome of this skill.

This permits clean unchanged-base versus fresh-adapter comparisons with identical
typed scopes, vocabulary, construction assistance and strict functional scoring.
Teacher-forced success or choosing a hard-coded tool name alone is insufficient.
Measure selecting relation, operands, literal/type and exact dependencies, then
accepted assembled behavior. Training-record reproduction is learning/fitting evidence
only; genuinely withheld structural families are needed for transfer claims.

   typed-step cohort, expert targets and independent withholding; do not reuse

2. Qualify deterministic B partial-state/update serialization and assembler over
   unchanged seal/validate/expand/execute helpers, plus mutation controls. This is
   construction tooling qualification, not semantic implementation permission.
3. Capture expert before/after states and explicit chosen updates. Admit each after
   endpoint acceptance. For C capture actual calls/responses using the supported
   existing dispatcher; do not invent observed AI trajectories.
4. Measure exact B/C target/context tokens and solve the matched-budget schedule.
   If C cannot be matched, authorize A/B only. Preserve expert and actual AI labels.
5. Only after these gates and separate training authorization consider the fresh
   matched20-update pilot. Existing stack mechanics make it technically plausible;
   current supervision/evaluation gaps make an immediate training comparison unjustified.

The recommended next experiment is this **no-training data/interface qualification**,
not another full-package smoke or the automatic execution of a curriculum stage.
